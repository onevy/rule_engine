# 规则引擎数据库设计文档

## 文档信息
- **文档版本**: v1.0
- **创建日期**: 2025-11-09
- **数据库版本**: MySQL 8.0+
- **字符集**: utf8mb4
- **排序规则**: utf8mb4_general_ci

## 1. 数据库概述

### 1.1 设计原则
- **规范化设计**: 采用第三范式(3NF)设计,减少数据冗余
- **性能优化**: 合理设计索引,支持高并发查询
- **扩展性**: 预留扩展字段,支持业务迭代
- **数据完整性**: 使用外键约束、唯一约束保证数据一致性
- **审计追溯**: 所有核心表包含创建人、创建时间、修改人、修改时间字段

### 1.2 命名规范
- **表名**: 小写字母+下划线,如 `business_scene`
- **字段名**: 小写字母+下划线,如 `scene_code`
- **主键**: 统一命名为 `id`,使用 BIGINT AUTO_INCREMENT
- **索引命名**:
  - 普通索引: `idx_表名_字段名`
  - 唯一索引: `uk_表名_字段名`
  - 外键: `fk_表名_关联表名`
- **时间字段**: 创建时间 `create_time`,更新时间 `update_time`
- **逻辑删除**: `is_deleted` (0-未删除, 1-已删除)

## 3. 核心表设计

### 3.1 业务场景表 (business_scene)

存储不同业务场景的配置信息,如传染病上报、处方审核等。

```sql
CREATE TABLE `business_scene` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `scene_code` VARCHAR(50) NOT NULL COMMENT '场景编码,如 INFECTIOUS_DISEASE',
  `scene_name` VARCHAR(100) NOT NULL COMMENT '场景名称',
  `scene_desc` VARCHAR(500) DEFAULT NULL COMMENT '场景描述',
  `adapter_class` VARCHAR(200) NOT NULL COMMENT '适配器类全限定名',
  `status` TINYINT NOT NULL DEFAULT 1 COMMENT '状态: 0-禁用, 1-启用',
  `sort_order` INT DEFAULT 0 COMMENT '排序号',
  `create_by` VARCHAR(50) NOT NULL COMMENT '创建人',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by` VARCHAR(50) DEFAULT NULL COMMENT '更新人',
  `update_time` DATETIME DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除: 0-否, 1-是',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_scene_code` (`scene_code`) USING BTREE,
  KEY `idx_status` (`status`) USING BTREE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='业务场景表';
```

**字段说明**:
- `scene_code`: 全局唯一的场景编码,用于程序中引用
- `adapter_class`: 对应的业务适配器类名,如 `com.example.adapter.InfectiousDiseaseAdapter`
- `status`: 控制场景是否可用,禁用后该场景下的规则不会执行

### 3.2 字段元数据表 (field_metadata)

存储各业务场景可用的字段定义。

```sql
CREATE TABLE `field_metadata` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `scene_code` VARCHAR(50) NOT NULL COMMENT '所属场景编码',
  `field_code` VARCHAR(100) NOT NULL COMMENT '字段编码,如 diagnosis_code',
  `field_name` VARCHAR(100) NOT NULL COMMENT '字段中文名称',
  `field_type` VARCHAR(20) NOT NULL COMMENT '字段类型: String, Number, Date, Boolean',
  `data_source` VARCHAR(100) DEFAULT NULL COMMENT '数据来源说明',
  `supported_operators` VARCHAR(500) NOT NULL COMMENT '支持的操作符,逗号分隔',
  `value_range` VARCHAR(500) DEFAULT NULL COMMENT '值域说明',
  `category` VARCHAR(50) DEFAULT NULL COMMENT '字段分类,如 诊断、检验、检查',
  `sort_order` INT DEFAULT 0 COMMENT '排序号',
  `is_required` TINYINT DEFAULT 0 COMMENT '是否必填: 0-否, 1-是',
  `create_by` VARCHAR(50) NOT NULL COMMENT '创建人',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by` VARCHAR(50) DEFAULT NULL COMMENT '更新人',
  `update_time` DATETIME DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除: 0-否, 1-是',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_scene_field` (`scene_code`, `field_code`) USING BTREE,
  KEY `idx_scene_code` (`scene_code`) USING BTREE,
  KEY `idx_field_type` (`field_type`) USING BTREE,
  KEY `idx_category` (`category`) USING BTREE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='字段元数据表';
```

**字段说明**:
- `supported_operators`: 存储支持的操作符,如 "EQ,IN,GT,LT"
- `value_range`: 字段值的范围或枚举值说明
- `scene_code + field_code`: 联合唯一索引,保证同一场景下字段编码唯一

### 3.3 规则组表 (rule_group)

对规则进行分组管理,便于组织和展示。

```sql
CREATE TABLE `rule_group` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `scene_code` VARCHAR(50) NOT NULL COMMENT '所属场景编码',
  `group_code` VARCHAR(100) NOT NULL COMMENT '规则组编码',
  `group_name` VARCHAR(100) NOT NULL COMMENT '规则组名称',
  `group_desc` VARCHAR(500) DEFAULT NULL COMMENT '规则组描述',
  `parent_id` BIGINT DEFAULT 0 COMMENT '父级ID, 0表示根节点',
  `sort_order` INT DEFAULT 0 COMMENT '排序号',
  `create_by` VARCHAR(50) NOT NULL COMMENT '创建人',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by` VARCHAR(50) DEFAULT NULL COMMENT '更新人',
  `update_time` DATETIME DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除: 0-否, 1-是',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_group_code` (`group_code`) USING BTREE,
  KEY `idx_scene_code` (`scene_code`) USING BTREE,
  KEY `idx_parent_id` (`parent_id`) USING BTREE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='规则组表';
```

**字段说明**:
- `parent_id`: 支持树形结构,可实现规则的层级分组
- `group_code`: 全局唯一的规则组编码

### 3.4 规则定义表 (rule_definition)

存储规则的基本信息和配置。

```sql
CREATE TABLE `rule_definition` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `rule_code` VARCHAR(100) NOT NULL COMMENT '规则编码',
  `rule_name` VARCHAR(100) NOT NULL COMMENT '规则名称',
  `rule_desc` VARCHAR(500) DEFAULT NULL COMMENT '规则描述',
  `scene_code` VARCHAR(50) NOT NULL COMMENT '所属场景编码',
  `group_id` BIGINT DEFAULT NULL COMMENT '所属规则组ID',
  `rule_type` VARCHAR(20) NOT NULL COMMENT '规则类型: ALERT-预警, AUDIT-审核, CONTROL-管控',
  `priority` INT DEFAULT 0 COMMENT '优先级: 数值越大优先级越高',
  `status` TINYINT NOT NULL DEFAULT 1 COMMENT '状态: 0-禁用, 1-启用, 2-草稿',
  `effective_start_time` DATETIME DEFAULT NULL COMMENT '生效开始时间',
  `effective_end_time` DATETIME DEFAULT NULL COMMENT '生效结束时间',
  `drl_content` TEXT COMMENT '编译后的DRL规则内容',
  `json_config` TEXT NOT NULL COMMENT 'JSON格式的规则配置',
  `version` INT DEFAULT 1 COMMENT '版本号',
  `create_by` VARCHAR(50) NOT NULL COMMENT '创建人',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_by` VARCHAR(50) DEFAULT NULL COMMENT '更新人',
  `update_time` DATETIME DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  `is_deleted` TINYINT NOT NULL DEFAULT 0 COMMENT '逻辑删除: 0-否, 1-是',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_rule_code` (`rule_code`) USING BTREE,
  KEY `idx_scene_code` (`scene_code`) USING BTREE,
  KEY `idx_group_id` (`group_id`) USING BTREE,
  KEY `idx_status` (`status`) USING BTREE,
  KEY `idx_rule_type` (`rule_type`) USING BTREE,
  KEY `idx_create_time` (`create_time`) USING BTREE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='规则定义表';
```

**字段说明**:
- `json_config`: 存储JSON格式的规则配置,用于前端展示和编辑
- `drl_content`: 编译后的Drools DRL规则,用于规则引擎执行
- `effective_start_time/effective_end_time`: 控制规则的生效时间范围
- `priority`: 当多条规则匹配时,优先级高的规则先执行
- `version`: 规则版本号,支持规则版本管理

### 3.5 条件组表 (condition_group)

存储规则的条件组信息,支持AND/OR逻辑嵌套。

```sql
CREATE TABLE `condition_group` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `rule_id` BIGINT NOT NULL COMMENT '所属规则ID',
  `parent_group_id` BIGINT DEFAULT 0 COMMENT '父条件组ID, 0表示根节点',
  `group_logic` VARCHAR(10) NOT NULL DEFAULT 'AND' COMMENT '组内逻辑: AND, OR',
  `group_level` INT DEFAULT 1 COMMENT '嵌套层级',
  `sort_order` INT DEFAULT 0 COMMENT '排序号',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  KEY `idx_rule_id` (`rule_id`) USING BTREE,
  KEY `idx_parent_group_id` (`parent_group_id`) USING BTREE,
  CONSTRAINT `fk_condition_group_rule` FOREIGN KEY (`rule_id`) REFERENCES `rule_definition` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='条件组表';
```

**字段说明**:
- `parent_group_id`: 支持嵌套的条件组结构
- `group_logic`: AND表示组内所有条件都要满足,OR表示满足任一条件即可
- `group_level`: 记录嵌套深度,便于查询和展示

### 3.6 规则条件表 (rule_condition)

存储具体的规则条件配置。

```sql
CREATE TABLE `rule_condition` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `rule_id` BIGINT NOT NULL COMMENT '所属规则ID',
  `group_id` BIGINT NOT NULL COMMENT '所属条件组ID',
  `field_code` VARCHAR(100) NOT NULL COMMENT '字段编码',
  `operator` VARCHAR(20) NOT NULL COMMENT '操作符: EQ, IN, GT, LT等',
  `field_value` TEXT COMMENT '字段值(JSON格式)',
  `value_type` VARCHAR(20) NOT NULL COMMENT '值类型: CONSTANT-常量, FIELD-字段, ARRAY-数组',
  `sort_order` INT DEFAULT 0 COMMENT '排序号',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `update_time` DATETIME DEFAULT NULL ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  KEY `idx_rule_id` (`rule_id`) USING BTREE,
  KEY `idx_group_id` (`group_id`) USING BTREE,
  KEY `idx_field_code` (`field_code`) USING BTREE,
  CONSTRAINT `fk_rule_condition_rule` FOREIGN KEY (`rule_id`) REFERENCES `rule_definition` (`id`) ON DELETE CASCADE,
  CONSTRAINT `fk_rule_condition_group` FOREIGN KEY (`group_id`) REFERENCES `condition_group` (`id`) ON DELETE CASCADE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='规则条件表';
```

**字段说明**:
- `field_value`: 使用TEXT类型存储,支持数组、对象等复杂值(JSON格式)
- `value_type`: 区分常量值、字段引用、数组值等不同类型
- 外键约束: 级联删除,删除规则时自动删除关联的条件

### 3.7 规则执行日志表 (rule_execution_log)

记录规则执行的详细日志,用于审计和问题排查。

```sql
CREATE TABLE `rule_execution_log` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',
  `trace_id` VARCHAR(64) NOT NULL COMMENT '链路追踪ID',
  `rule_id` BIGINT NOT NULL COMMENT '规则ID',
  `rule_code` VARCHAR(100) NOT NULL COMMENT '规则编码',
  `scene_code` VARCHAR(50) NOT NULL COMMENT '场景编码',
  `business_id` VARCHAR(100) DEFAULT NULL COMMENT '业务ID',
  `input_data` TEXT COMMENT '输入数据(JSON格式)',
  `execution_result` VARCHAR(20) NOT NULL COMMENT '执行结果: HIT-命中, MISS-未命中, ERROR-异常',
  `hit_rules` TEXT COMMENT '命中的规则列表(JSON格式)',
  `execution_time` INT DEFAULT 0 COMMENT '执行耗时(毫秒)',
  `error_message` TEXT COMMENT '错误信息',
  `execute_by` VARCHAR(50) DEFAULT NULL COMMENT '执行人',
  `execute_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '执行时间',
  `server_ip` VARCHAR(50) DEFAULT NULL COMMENT '服务器IP',
  PRIMARY KEY (`id`),
  KEY `idx_trace_id` (`trace_id`) USING BTREE,
  KEY `idx_rule_id` (`rule_id`) USING BTREE,
  KEY `idx_rule_code` (`rule_code`) USING BTREE,
  KEY `idx_scene_code` (`scene_code`) USING BTREE,
  KEY `idx_business_id` (`business_id`) USING BTREE,
  KEY `idx_execute_time` (`execute_time`) USING BTREE,
  KEY `idx_execution_result` (`execution_result`) USING BTREE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='规则执行日志表';
```

**字段说明**:
- `trace_id`: 全局唯一的追踪ID,用于分布式环境下的日志关联
- `input_data`: 记录规则执行时的输入数据,便于问题重现
- `hit_rules`: 记录命中的所有规则信息
- `execution_time`: 记录执行耗时,用于性能分析
- 建议按月分表,保留近6个月数据

### 3.8 用户表 (user)

存储系统用户信息。

```sql
CREATE TABLE `user` (
  `id` BIGINT NOT NULL AUTO_INCREMENT COMMENT '主键ID',

  `last_login_ip` VARCHAR(50) DEFAULT NULL COMMENT '最后登录IP',
  `create_by` VARCHAR(50) NOT NULL COMMENT '创建人',
  `create_time` DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',

  KEY `idx_status` (`status`) USING BTREE,

**字段说明**:
- `password`: 使用BCrypt等强加密算法加密存储

### 3.11 角色权限表 (role_permission)

```

**字段说明**:
- `resource_type`: 区分不同类型的资源
- `resource_code`: 资源的唯一标识,如菜单编码、接口路径等
- `permission`: 具体的操作权限

## 4. 索引设计说明

### 4.1 主键索引
- 所有表使用 `id` 作为主键,BIGINT AUTO_INCREMENT
- 主键索引自动创建,采用 B+Tree 结构

### 4.2 唯一索引
- `business_scene.uk_scene_code`: 保证场景编码唯一
- `field_metadata.uk_scene_field`: 保证场景下字段编码唯一
- `rule_definition.uk_rule_code`: 保证规则编码唯一
- `user.uk_username`: 保证用户名唯一
- `role.uk_role_code`: 保证角色编码唯一

### 4.3 普通索引
- **高频查询字段**: status, scene_code, rule_id 等
- **时间字段**: create_time, execute_time (支持时间范围查询)
- **外键字段**: 所有外键都建立索引,提升JOIN性能
- **业务查询字段**: business_id, trace_id (支持业务查询)

### 4.4 索引优化建议
- **避免过多索引**: 每个表索引数量控制在5个以内
- **覆盖索引**: 对于查询频繁的字段组合,考虑建立联合索引
- **索引选择性**: 优先为选择性高的字段建立索引
- **定期维护**: 使用 `OPTIMIZE TABLE` 优化索引碎片

## 6. 性能优化策略

### 6.1 分表分库策略

#### 6.1.1 rule_execution_log 分表
- **分表规则**: 按月分表
- **表名格式**: `rule_execution_log_YYYYMM`
- **保留策略**: 保留近6个月数据,历史数据归档到冷存储

```sql

```

#### 6.1.2 audit_log 分表
- **分表规则**: 按月分表
- **表名格式**: `audit_log_YYYYMM`
- **保留策略**: 保留1年数据

### 6.2 缓存策略

#### 6.2.1 应用层缓存
- **场景配置**: 缓存 business_scene 数据,TTL 30分钟
- **字段元数据**: 缓存 field_metadata 数据,TTL 30分钟
- **规则定义**: 缓存启用状态的规则,TTL 10分钟
- **用户权限**: 缓存用户角色权限,TTL 15分钟

#### 6.2.2 数据库查询缓存
- 开启MySQL查询缓存 (MySQL 5.7)
- 或使用Redis作为查询结果缓存层

### 6.3 读写分离
- **主库**: 处理写操作和实时性要求高的读操作
- **从库**: 处理查询、统计等读操作
- **延迟监控**: 监控主从复制延迟,保证数据一致性

### 6.4 SQL优化
- **避免SELECT ***: 只查询需要的字段
- **使用LIMIT**: 分页查询必须使用LIMIT
- **索引覆盖**: 尽量使用覆盖索引避免回表
- **EXPLAIN分析**: 定期使用EXPLAIN分析慢查询

## 7. 数据备份策略

### 7.1 备份方案
- **全量备份**: 每天凌晨2点进行全量备份

### 10.2 常用SQL示例

#### 查询规则及其条件

```sql
SELECT
  rd.rule_code,
  rd.rule_name,
  cg.group_logic,
  rc.field_code,
  rc.operator,
  rc.field_value
FROM rule_definition rd
LEFT JOIN condition_group cg ON rd.id = cg.rule_id
LEFT JOIN rule_condition rc ON cg.id = rc.group_id
WHERE rd.scene_code = 'INFECTIOUS_DISEASE'
  AND rd.status = 1
  AND rd.is_deleted = 0
ORDER BY rd.priority DESC, rc.sort_order;
```

#### 查询用户权限

```sql
SELECT
  u.username,
  r.role_name,
  rp.resource_type,
  rp.resource_code,
  rp.permission
FROM user u
INNER JOIN user_role ur ON u.id = ur.user_id
INNER JOIN role r ON ur.role_id = r.id
LEFT JOIN role_permission rp ON r.id = rp.role_id
WHERE u.username = 'admin'
  AND u.is_deleted = 0
  AND r.status = 1;
```

#### 统计规则执行情况

```sql
SELECT
  DATE(execute_time) as execute_date,
  scene_code,
  execution_result,
  COUNT(*) as total_count,
  AVG(execution_time) as avg_time,
  MAX(execution_time) as max_time
FROM rule_execution_log
WHERE execute_time >= DATE_SUB(NOW(), INTERVAL 7 DAY)
GROUP BY DATE(execute_time), scene_code, execution_result
ORDER BY execute_date DESC, scene_code;
```
