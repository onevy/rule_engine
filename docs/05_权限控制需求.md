# 权限控制需求说明 V1.0

## 一、文档说明

本文档定义规则引擎系统的权限控制需求，包括用户角色、权限定义、数据权限、操作审计等内容。

---

## 二、权限控制总体要求

### 2.1 设计原则

1. **最小权限原则**: 用户仅拥有完成工作所需的最小权限
2. **职责分离**: 不同角色权限隔离，避免权限集中
3. **可追溯性**: 所有敏感操作可追溯到具体用户
4. **灵活配置**: 支持权限的动态配置和调整

### 2.2 权限模型

采用**RBAC（基于角色的访问控制）**模型：

```
用户(User) → 角色(Role) → 权限(Permission) → 资源(Resource)
```

## 四、权限资源定义

### 4.1 资源类型

| 资源类型 | 资源编码 | 说明 |
|---------|---------|------|
| 场景 | scene | 业务场景（如传染病报卡、处方审核） |
| 规则组 | rule_group | 规则分组 |
| 规则 | rule | 具体规则 |
| 元数据 | metadata | 字段元数据 |
| 执行日志 | execution_log | 规则执行记录 |
| 审计日志 | audit_log | 操作审计记录 |
| 用户 | user | 系统用户 |
| 角色 | role | 系统角色 |

### 4.2 操作权限定义

| 操作编码 | 操作名称 | 说明 |
|---------|---------|------|
| view | 查看 | 查看资源信息 |
| create | 创建 | 创建新资源 |
| update | 更新 | 修改现有资源 |
| delete | 删除 | 删除资源 |
| execute | 执行 | 执行规则 |
| export | 导出 | 导出数据 |
| import | 导入 | 导入数据 |
| test | 测试 | 测试规则 |
| enable | 启用 | 启用资源 |
| disable | 禁用 | 禁用资源 |
| rollback | 回滚 | 版本回滚 |

### 4.3 权限编码规范

权限编码格式：`<资源类型>:<操作>`

示例：
- `scene:view` - 查看场景
- `rule:create` - 创建规则
- `rule:update` - 更新规则
- `rule:delete` - 删除规则
- `rule:execute` - 执行规则
- `audit_log:view` - 查看审计日志

## 五、数据权限控制

### 5.1 场景级数据隔离

**需求**: 不同用户只能访问其负责的业务场景

**实现方式**:
- 在用户表中关联用户负责的场景列表
- 查询规则时自动过滤用户无权访问的场景
- 场景管理员（SCENE_ADMIN）仅能管理授权场景

**数据表设计**:
```sql
-- 用户场景授权表
CREATE TABLE user_scene_auth (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL COMMENT '用户ID',
    scene_id BIGINT NOT NULL COMMENT '场景ID',
    created_time DATETIME,
    UNIQUE KEY uk_user_scene (user_id, scene_id),
    INDEX idx_user_id (user_id),
    INDEX idx_scene_id (scene_id)
) COMMENT='用户场景授权表';
```

### 5.2 规则组级数据隔离

**需求**: 某些用户只能访问特定规则组

**实现方式**:
- 在规则组上设置可见性范围
- 支持公开（所有人可见）和私有（仅创建者可见）

**字段扩展**:
```sql
ALTER TABLE rule_group
ADD COLUMN visibility VARCHAR(20) DEFAULT 'PUBLIC' COMMENT '可见性:PUBLIC-公开,PRIVATE-私有',
ADD COLUMN owner_id BIGINT COMMENT '所有者ID';
```

### 5.3 数据脱敏

**需求**: 执行日志中的敏感数据需要脱敏展示

**敏感字段**:
- 患者姓名
- 身份证号
- 手机号
- 病历号

**脱敏规则**:
- 姓名：张\*\*
- 身份证号：110\*\*\*\*\*\*\*\*\*\*1234
- 手机号：138\*\*\*\*5678
- 病历号：HIS\*\*\*\*\*234

**实现方式**:
- 在查询日志API中自动脱敏
- 超级管理员和审计员可查看原始数据（需审批）

CREATE TABLE audit_log (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    operation_type VARCHAR(50) NOT NULL COMMENT '操作类型:CREATE,UPDATE,DELETE,ENABLE,DISABLE,ROLLBACK',
    resource_type VARCHAR(50) NOT NULL COMMENT '资源类型:RULE,SCENE,METADATA,USER,ROLE',

    resource_code VARCHAR(100) COMMENT '资源编码',
    operation_desc VARCHAR(500) COMMENT '操作描述',
    before_content TEXT COMMENT '操作前内容(JSON)',
    after_content TEXT COMMENT '操作后内容(JSON)',
    operator_id BIGINT NOT NULL COMMENT '操作人ID',
    operator_name VARCHAR(50) COMMENT '操作人姓名',
    operator_ip VARCHAR(50) COMMENT '操作IP',
    operation_time DATETIME NOT NULL COMMENT '操作时间',
    result VARCHAR(20) COMMENT '操作结果:SUCCESS,FAIL',
    error_message TEXT COMMENT '错误信息',
    INDEX idx_operation_type (operation_type),
    INDEX idx_resource_type (resource_type),
    INDEX idx_operator_id (operator_id),
    INDEX idx_operation_time (operation_time)

## 七、身份认证与鉴权

### 7.1 身份认证

**认证方式**:
- 基于JWT Token的认证
- Token有效期：2小时
- 支持Token刷新

**登录流程**:
1. 用户输入用户名和密码
2. 后端验证用户名密码
3. 验证通过，生成JWT Token
4. 前端存储Token（LocalStorage）
5. 后续请求在Header中携带Token

**Token格式**:
```json
{
  "userId": 1001,
  "username": "zhangsan",
  "roles": ["RULE_ADMIN"],
  "sceneIds": [1, 2, 3],
  "exp": 1704787200
}
```

### 7.2 接口鉴权

**鉴权流程**:
1. 拦截器验证Token有效性
2. 解析Token获取用户信息和角色
3. 根据请求的资源和操作检查权限
4. 权限不足返回403 Forbidden
5. Token过期返回401 Unauthorized

**权限检查示例**:
```java
@PreAuthorize("hasPermission('rule', 'create')")
public Result<Long> createRule(@RequestBody RuleDefinitionDTO dto) {
    // 创建规则逻辑
}

@PreAuthorize("hasPermission('rule', 'update') and hasSceneAccess(#dto.sceneId)")
public Result<Void> updateRule(@PathVariable Long ruleId, @RequestBody RuleDefinitionDTO dto) {
    // 更新规则逻辑
}
```

## 八、密码安全要求

### 8.1 密码复杂度

- 最小长度：8位
- 必须包含：大写字母、小写字母、数字
- 建议包含：特殊字符(!@#$%^&*)
- 不能包含：用户名、常见弱密码

### 8.2 密码存储

- 使用BCrypt算法加密存储
- 不存储明文密码
- 加盐处理

### 8.3 密码策略

- 首次登录强制修改密码
- 密码定期更换（90天）
- 密码不能与近3次历史密码相同
- 连续5次输入错误锁定账户（30分钟）

## 九、接口访问控制

### 9.1 IP白名单（可选）

**需求**: 某些敏感接口仅允许特定IP访问

**适用接口**:
- 规则导入接口
- 用户管理接口
- 权限配置接口

**实现方式**:
- 在配置文件中配置IP白名单
- 拦截器检查请求IP
- 非白名单IP拒绝访问

### 9.2 接口限流

**需求**: 防止接口被恶意调用

**限流策略**:
- 单用户限流：100次/分钟
- 单IP限流：500次/分钟
- 规则执行接口：1000次/分钟

**实现方式**:
- 基于Redis的令牌桶算法
- 超过限制返回429 Too Many Requests

## 十、前端权限控制

### 10.1 菜单权限

**需求**: 根据用户角色显示不同菜单

**实现方式**:
- 前端根据用户角色动态渲染菜单
- 无权限的菜单不显示

**菜单权限配置**:
```javascript
const menuConfig = [
  {
    path: '/scene',
    name: '场景管理',
    roles: ['SUPER_ADMIN', 'RULE_ADMIN', 'SCENE_ADMIN']
  },
  {
    path: '/rule',
    name: '规则管理',
    roles: ['SUPER_ADMIN', 'RULE_ADMIN', 'SCENE_ADMIN', 'RULE_OPERATOR']
  },
  {
    path: '/audit',
    name: '审计日志',
    roles: ['SUPER_ADMIN', 'AUDITOR']
  },
  {
    path: '/user',
    name: '用户管理',
    roles: ['SUPER_ADMIN']
  }
]
```

### 10.2 按钮权限

**需求**: 页面中的按钮根据权限显示/隐藏

**实现方式**:
- 使用自定义指令v-permission
- 无权限的按钮不显示

**使用示例**:
```vue
<el-button
  v-permission="'rule:create'"
  type="primary"
  @click="createRule">
  新增规则
</el-button>

<el-button
  v-permission="'rule:delete'"
  type="danger"
  @click="deleteRule">
  删除规则
</el-button>
```

### 10.3 字段权限（可选）

**需求**: 某些敏感字段仅特定角色可见

**实现方式**:
- 后端返回字段权限信息
- 前端根据权限控制字段显示

## 十一、安全加固建议

### 11.1 HTTPS强制

- 生产环境强制使用HTTPS
- 禁止HTTP明文传输

### 11.2 CORS配置

- 配置允许的域名白名单
- 禁止所有域名访问（防止CSRF）

### 11.3 SQL注入防护

- 使用参数化查询
- 禁止拼接SQL语句
- 输入参数验证和过滤

### 11.4 XSS防护

- 前端对用户输入进行转义
- 后端返回数据时进行HTML编码
- 设置HTTP响应头：X-XSS-Protection

### 11.5 CSRF防护

- 使用CSRF Token
- 验证Referer头
- SameSite Cookie属性
