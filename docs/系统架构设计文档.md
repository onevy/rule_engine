## 一、架构设计总览

### 1.1 设计原则

1. **分层架构**: 清晰的层次划分，每层职责明确
2. **业务解耦**: 规则引擎核心与具体业务解耦
3. **高内聚低耦合**: 模块内部高内聚，模块间低耦合
4. **可扩展性**: 易于扩展新业务场景和新功能
5. **高性能**: 规则预编译、缓存、并行执行
6. **高可用**: 异常处理、日志记录、监控告警

### 1.2 架构风格

- **分层架构** (Layered Architecture)
- **适配器模式** (Adapter Pattern)
- **策略模式** (Strategy Pattern)
- **模板方法模式** (Template Method Pattern)

#### 3.2.2 传染病报卡适配器

```java
package com.ruleengine.adapter.impl;

@Component
public class InfectiousDiseaseAdapter implements BusinessAdapter {

    @Override
    public String getSceneCode() {
        return "INFECTIOUS_DISEASE_REPORT";
    }

    @Override
    public Map<String, Object> preProcess(Object originalData) {
        InfectiousDiseaseRequest request = (InfectiousDiseaseRequest) originalData;

        Map<String, Object> inputData = new HashMap<>();
        inputData.put("diagnosis_code", request.getDiagnosisCode());
        inputData.put("diagnosis_name", request.getDiagnosisName());
        inputData.put("lab_hiv", request.getLabHiv());
        // ... 其他字段映射

        return inputData;
    }

    @Override
    public Object postProcess(RuleResult ruleResult) {
        InfectiousDiseaseResponse response = new InfectiousDiseaseResponse();

        if (ruleResult.isMatched()) {
            response.setNeedReport(true);
            response.setDiseaseCode((String) ruleResult.getOutputData().get("disease_code"));
            response.setDiseaseName((String) ruleResult.getOutputData().get("disease_name"));
        } else {
            response.setNeedReport(false);
        }

        return response;
    }
}
```

### 5.3 并发控制

#### 5.3.1 KieSession 线程安全

```java
// 问题：KieSession不是线程安全的
// 解决：每次执行创建新的Session，使用后dispose

@Override
public RuleResult execute(RuleContext context) {
    KieBase kieBase = getOrLoadKieBase(context.getSceneCode());
    KieSession session = kieBase.newKieSession();  // 创建新Session

    try {
        // 执行规则
        session.setGlobal("ruleResult", new RuleResult());
        session.insert(context.getInputData());
        session.fireAllRules();
        return (RuleResult) session.getGlobal("ruleResult");
    } finally {
        session.dispose();  // 释放资源
    }
}
```

#### 5.3.2 KieBase 缓存并发

```java
// 使用ConcurrentHashMap保证并发安全
private final Map<String, KieBase> kieBaseCache = new ConcurrentHashMap<>();

// computeIfAbsent是线程安全的

    return kieBaseCache.computeIfAbsent(sceneCode, this::loadKieBase);
}
```

```java
@Configuration
@EnableGlobalMethodSecurity(prePostEnabled = true)
public class SecurityConfig {

    @Bean
    public PermissionEvaluator permissionEvaluator() {
        return new RuleEnginePermissionEvaluator();
    }
}

public class RuleEnginePermissionEvaluator implements PermissionEvaluator {

    @Override
    public boolean hasPermission(Authentication auth, Object targetDomainObject, Object permission) {
        // 权限检查逻辑
        User user = (User) auth.getPrincipal();
        String permissionStr = (String) permission;

        return user.getPermissions().contains(permissionStr);
    }
}
```

## 八、性能优化设计

### 8.1 规则编译优化

- **规则预编译**: 系统启动时预编译所有规则
- **增量编译**: 规则变更时只编译变更的规则
- **编译缓存**: KieBase级别缓存

### 8.2 规则执行优化

- **无状态会话**: 对于无状态规则使用StatelessKieSession
- **并行执行**: 批量执行使用并行流
- **规则优先级**: 合理设置salience避免不必要的规则执行

### 8.3 数据库优化

- **索引优化**: 关键字段建立索引
- **分页查询**: 大数据量查询使用分页
- **连接池**: 合理配置数据库连接池
- **读写分离**: 高并发场景支持主从分离

### 8.4 缓存策略

```
┌──────────────────┐
│ L1: 应用内存缓存   │ → KieBase缓存
│ (ConcurrentHashMap)│
└──────────────────┘
         ↓
┌──────────────────┐
│ L2: Redis缓存(可选)│ → 热点数据缓存
│                  │   (场景元数据、规则列表等)
└──────────────────┘
         ↓
┌──────────────────┐
│ L3: 数据库        │ → 持久化存储
└──────────────────┘
```
