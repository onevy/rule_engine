# 规则引擎快速部署指南

## 1. 环境要求

### 1.1 开发环境
- JDK 11+
- Node.js 16+
- Maven 3.6+
- MySQL 8.0+
- Redis 6.0+

### 1.2 Docker部署
- Docker 20.10+
- Docker Compose 2.0+

## 2. Docker一键部署（推荐）

### 2.1 克隆项目
```bash
git clone <repository-url>
cd rule_demo1
```

### 2.2 启动服务
```bash
# 赋予脚本执行权限
chmod +x deploy.sh

# 构建镜像
./deploy.sh build

# 启动服务
./deploy.sh start
```

### 2.3 访问系统
- 前端: http://localhost
- 后端API: http://localhost:8080
- API文档: http://localhost:8080/swagger-ui.html

### 2.4 其他命令
```bash
# 查看服务状态
./deploy.sh status

# 查看日志
./deploy.sh logs
./deploy.sh logs backend  # 只看后端日志

# 停止服务
./deploy.sh stop

# 重启服务
./deploy.sh restart

# 初始化数据库
./deploy.sh init-db

# 备份数据库
./deploy.sh backup-db
```

## 3. 本地开发部署

### 3.1 数据库准备
```bash
# 创建数据库
mysql -u root -p
CREATE DATABASE rule_engine DEFAULT CHARACTER SET utf8mb4;

# 执行初始化脚本
mysql -u root -p rule_engine < backend/src/main/resources/sql/schema.sql
mysql -u root -p rule_engine < backend/src/main/resources/sql/data.sql
```

### 3.2 后端启动
```bash
cd backend

# 修改配置文件（根据实际环境）
# vim src/main/resources/application-dev.yml

# 编译
mvn clean compile

# 运行
mvn spring-boot:run -Dspring-boot.run.profiles=dev
```

### 3.3 前端启动
```bash
cd frontend

# 安装依赖
npm install

# 开发模式运行
npm run dev

# 生产构建
npm run build
```

## 4. 配置说明

### 4.1 后端配置 (application-dev.yml)

```yaml
spring:
  datasource:
    url: jdbc:mysql://localhost:3306/rule_engine
    username: root
    password: your_password

  redis:
    host: 127.0.0.1
    port: 6379
    password: your_redis_password

jwt:
  secret: YourSecretKeyMustBeLongEnough
  expiration: 7200
```

### 4.2 前端配置 (.env.development)

```env
VITE_API_BASE_URL=http://localhost:8080/api
```

### 4.3 生产环境配置

修改 `docker-compose.yml` 中的环境变量：
- `MYSQL_ROOT_PASSWORD`: MySQL root密码
- `MYSQL_PASSWORD`: 应用数据库密码
- `JWT_SECRET`: JWT密钥（至少32位）
- `REDIS_PASSWORD`: Redis密码

## 6. 常见问题

### Q1: Docker启动失败
```bash
# 查看日志
docker-compose logs

# 检查端口占用
lsof -i :80
lsof -i :8080
lsof -i :3306
```

### Q2: 数据库连接失败
- 确认MySQL服务已启动
- 检查用户名密码是否正确
- 检查防火墙设置

### Q3: 前端无法访问后端API
- 检查nginx代理配置
- 确认后端服务已启动
- 检查CORS配置

### Q4: 内存不足
```bash
# 调整Docker内存限制
# 修改 docker-compose.yml 添加资源限制
deploy:
  resources:
    limits:
      memory: 2G
```

## 7. 性能调优

### 7.1 JVM参数调整
修改 `docker-compose.yml` 中的 `JAVA_OPTS`:
```yaml
JAVA_OPTS: "-Xms1g -Xmx2g -XX:+UseG1GC"
```

### 7.2 MySQL优化
```sql
-- 根据服务器内存调整
SET GLOBAL innodb_buffer_pool_size = 1073741824;  -- 1GB
```

### 7.3 Redis配置
```conf
maxmemory 512mb
maxmemory-policy allkeys-lru
```
