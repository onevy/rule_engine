# 业务场景详细需求说明 V1.0

## 一、文档说明

本文档详细描述规则引擎支持的三个业务场景：传染病报卡、处方审核、病案质控。每个场景包括业务背景、功能需求、数据字段、规则示例、输入输出接口等。

---

## 二、场景一：传染病报卡

### 2.1 业务背景

**业务说明**:
根据《中华人民共和国传染病防治法》规定，医疗机构在诊疗过程中发现法定传染病时，必须在规定时限内通过传染病报告信息系统进行报告。传染病分为甲类、乙类、丙类，不同级别有不同的报告时限要求。

**业务痛点**:
- 医生容易遗漏传染病上报
- 人工判断传染病是否需要上报效率低
- 不同传染病的上报规则复杂多变
- 需要结合诊断、检验、检查等多维度数据判断

**解决方案**:
通过规则引擎自动识别符合上报条件的传染病，实时提示医生进行上报，避免漏报、错报。

### 2.2 功能需求

#### 2.2.1 核心功能

1. **自动识别传染病**
   - 根据诊断编码/名称自动识别是否为法定传染病
   - 支持ICD-10诊断编码匹配
   - 支持诊断名称模糊匹配

2. **智能提示上报**
   - 满足诊断条件时，弹窗提示医生需要上报
   - 显示传染病名称、级别、上报类型
   - 提供一键生成报卡功能

3. **多维度条件判断**
   - 诊断满足规则：基于诊断数据判断
   - 满足提示规则：结合检验、检查数据进一步确认
   - 支持复杂的AND/OR逻辑组合

4. **重复报卡控制**
   - 设置时间窗口（如7天内）避免重复上报
   - 支持同一患者同一传染病的重复上报判断

5. **场景适配**
   - 门诊医生站
   - 住院医生站
   - 急诊医生站
   - 体检医生站
   - 无需处理（某些场景不上报）
   - 精确处理（严格匹配）
   - 无需处理（不触发上报）

#### 2.2.2 配置需求

1. **传染病基础配置**
   - 传染病名称
   - 传染病编码
   - 传染病级别（甲类、乙类、丙类）
   - 报卡类型（艾滋性病报卡、其他传染病报卡等）
   - 是否启用

2. **诊断满足规则配置**（参考原型图rule1.jpg）
   - 支持"或者"/"并且"逻辑切换
   - 支持多条件组
   - 每个条件组包含：
     - 关联条件（或者/并且）
     - 关联因素（诊断名称/诊断编码等）
     - 匹配符（包含in/左匹配/模糊匹配等）
     - 匹配值（支持多选、自由输入）

3. **满足提示规则配置**
   - 支持检验、检查、影像等多维度数据
   - 支持定量检验（数值比较）
   - 支持定性检验（枚举选择）
   - 支持文本检验（包含/不包含）

### 2.4 规则示例

#### 示例1：艾滋病报卡规则

**规则名称**: 艾滋病(HIV)报卡规则

**规则编码**: INFECTIOUS_HIV_001

**传染病信息**:
- 传染病名称：艾滋病
- 传染病编码：HIV / 101
- 传染病级别：乙类
- 报卡类型：艾滋性病报卡

**诊断满足规则**（OR逻辑）:
- 条件组1（AND）：诊断编码 包含 [B22.100, B22.200, B22.700, B22.701, B23.100, B23.200]
- 条件组2（AND）：诊断名称 左匹配 "B20"

**满足提示规则**（AND逻辑）:
- 血常规/白细胞计数(定量) >= 24.75
- 常规检验/血红蛋白(定性) 包含 [阳性、阴性]
- 尿常规/尿蛋白(文本) 包含 "*"
- CT/检查所见 包含 "双肺散在性病灶"
- 超声/诊断所见 不包含 "不明原因肺类"

**执行动作**:
- 返回need_report = true
- 返回disease_code = "HIV"
- 返回disease_name = "艾滋病"
- 返回report_type = "艾滋性病报卡"
- 弹窗提示："检测到艾滋病，请及时上报传染病报卡"

## 三、场景二：处方审核

### 3.1 业务背景

**业务说明**:
处方审核是医院药学部门对医生开具的处方进行合理性审查，包括用药适应症、药物剂量、药物相互作用、禁忌症等多个维度，确保患者用药安全。

**业务痛点**:
- 药品种类繁多，相互作用复杂
- 医生难以记住所有用药禁忌
- 特殊人群（儿童、孕妇、老人、肝肾功能异常）用药风险高
- 人工审核效率低，容易遗漏问题

**解决方案**:
通过规则引擎实时审核处方，自动识别不合理用药，给出用药建议和调整方案。

### 3.2 功能需求

#### 3.2.1 核心功能

1. **超剂量用药审核**
   - 根据患者年龄、体重、肝肾功能判断剂量是否合理
   - 支持成人剂量和儿童剂量的区分
   - 支持最大日剂量、单次剂量的校验

2. **药物相互作用检查**
   - 识别处方中药品的相互作用
   - 分级提示（严重、中度、轻度）
   - 给出联合用药建议

3. **禁忌症审核**
   - 根据患者诊断、既往史、过敏史判断是否有用药禁忌
   - 妊娠禁忌、哺乳期禁忌
   - 肝肾功能异常禁忌

4. **适应症审核**
   - 检查药品是否符合患者诊断
   - 提示超适应症用药

5. **重复用药检查**
   - 识别同类药品重复使用
   - 识别同成分药品重复使用

#### 3.2.2 配置需求

1. **药品基础数据**
   - 药品编码、名称、规格
   - 适应症、禁忌症
   - 常规剂量、最大剂量
   - 特殊人群用药说明

2. **审核规则配置**
   - 剂量规则（按年龄、体重、肝肾功能）
   - 相互作用规则
   - 禁忌症规则
   - 适应症规则

3. **审核严重程度**
   - 严重错误（必须修改）
   - 警告信息（建议修改）
   - 提示信息（仅提示）

### 3.3 数据字段

#### 3.3.1 输入数据

| 字段分类 | 字段编码 | 字段名称 | 数据类型 | 必填 | 说明 |
|---------|---------|---------|---------|-----|------|
| **药品数据** | drug_codes | 药品编码列表 | Array | 是 | 处方中所有药品编码 |
| | drug_names | 药品名称列表 | Array | 是 | 处方中所有药品名称 |
| | drug_doses | 药品剂量Map | Object | 是 | {药品编码: 剂量} |

| | drug_routes | 给药途径Map | Object | 否 | {药品编码: 途径} |
| **诊断数据** | diagnosis_codes | 诊断编码列表 | Array | 是 | 患者所有诊断 |
| **患者数据** | patient_age | 患者年龄 | Number | 是 | 岁 |

### 3.4 规则示例

#### 示例1：儿童布洛芬超剂量规则

**规则名称**: 儿童布洛芬超剂量审核

- 更换为妊娠期安全用药

#### 示例3：药物相互作用规则

**规则编码**: PRESCRIPTION_INTERACTION_001

**条件**:
- 药品编码列表 包含 "华法林"
- 药品编码列表 包含 "阿司匹林"

**审核问题**:
- 问题类型：药物相互作用
- 严重程度：中度
- 问题描述：华法林与阿司匹林联用可能增加出血风险

**建议**:
- 密切监测凝血功能
- 或考虑更换其他抗血小板药物

## 四、场景三：病案质控

### 4.1 业务背景

**业务说明**:
病案质控是医院对出院病历进行质量检查，确保病历内容完整、准确、规范，符合《病历书写基本规范》和医院管理要求。

**业务痛点**:
- 病历书写不规范，内容缺失
- 主要诊断与手术、费用不匹配
- 药占比、平均住院日等指标超标
- 人工抽查覆盖率低，问题发现滞后

**解决方案**:
通过规则引擎自动检查病历完整性、逻辑一致性、质控指标合规性，给出质量评分和改进建议。

### 4.2 功能需求

#### 4.2.1 核心功能

1. **病历完整性检查**
   - 入院记录、病程记录、出院小结是否完整
   - 手术记录、知情同意书是否缺失
   - 检验、检查报告是否完整

2. **逻辑一致性检查**
   - 主要诊断与手术是否匹配
   - 主要诊断与主要治疗措施是否一致
   - 入院诊断与出院诊断是否合理

3. **质控指标检查**
   - 药占比是否超标
   - 平均住院日是否超标
   - 抗菌药物使用是否合理
   - 检查费用占比是否合理

4. **质量评分**
   - 根据问题数量和严重程度计算质量分数
   - 分级：优秀(90-100)、良好(80-89)、合格(60-79)、不合格(<60)

5. **改进建议**
   - 针对每个质量问题给出改进建议
   - 提供参考案例和规范文档

#### 4.2.2 配置需求

1. **质控规则配置**
   - 必填项规则
   - 逻辑一致性规则
   - 指标阈值规则

2. **评分规则配置**
   - 不同问题的扣分标准
   - 严重问题、一般问题的权重

3. **科室个性化规则**
   - 不同科室的特殊要求
   - 不同疾病的特殊要求

### 4.4 规则示例

#### 示例1：主要诊断缺失规则

**规则名称**: 主要诊断缺失检查

**规则编码**: MEDICAL_RECORD_DIAGNOSIS_001

**条件**:
- 主要诊断 为空 或 主要诊断 = ""

**质量问题**:
- 问题类型：内容缺失
- 严重程度：严重
- 问题描述：主要诊断缺失
- 扣分：-10分

**改进建议**:
- 请完善主要诊断信息
- 主要诊断应选择本次住院治疗的主要疾病

#### 示例2：药占比超标规则

**规则名称**: 药占比超标检查

**规则编码**: MEDICAL_RECORD_DRUG_RATIO_001

**条件**:
- 药占比 > 30%

**质量问题**:
- 问题类型：指标超标
- 严重程度：中度
- 问题描述：药占比超过30%标准
- 扣分：-5分

**改进建议**:
- 优化用药结构，减少非必要药品使用
- 加强抗菌药物管理

#### 示例3：手术记录缺失规则

**规则名称**: 手术记录缺失检查

**规则编码**: MEDICAL_RECORD_OPERATION_001

**条件**:
- 有手术 = true
- 有手术记录 = false

**质量问题**:
- 问题类型：内容缺失
- 严重程度：严重
- 问题描述：患者有手术但缺少手术记录
- 扣分：-10分

**改进建议**:
- 请补充完整的手术记录
- 手术记录应在术后24小时内完成

#### 示例4：平均住院日超标规则

**规则名称**: 平均住院日超标检查

**规则编码**: MEDICAL_RECORD_LOS_001

**条件**:
- 住院天数 > 15天
- 科室 = "内科"

**质量问题**:
- 问题类型：指标超标
- 严重程度：轻度
- 问题描述：内科住院天数超过15天
- 扣分：-3分

**改进建议**:
- 优化诊疗流程，缩短住院时间
- 加强出院计划管理

## 五、场景对比总结

| 维度 | 传染病报卡 | 处方审核 | 病案质控 |
|-----|----------|---------|---------|
| **业务性质** | 法规强制性上报 | 用药安全审核 | 病历质量管理 |
| **触发时机** | 医生下诊断时 | 医生开处方时 | 患者出院后 |
| **数据来源** | 诊断+检验+检查 | 处方+诊断+患者信息 | 病历+费用+质控指标 |
| **判断逻辑** | OR逻辑为主 | AND逻辑为主 | 完整性+一致性检查 |
| **输出结果** | 是否上报+报卡类型 | 审核问题+用药建议 | 质量分数+改进建议 |
| **严重程度** | 高（法律责任） | 高（患者安全） | 中（管理要求） |
| **实时性要求** | 实时提示 | 实时阻断 | 可批量处理 |
| **规则复杂度** | 中 | 高 | 中 |
