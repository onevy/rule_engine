## 一、引言

### 1.1 编写目的

本文档详细描述通用规则引擎系统的需求规格，作为系统设计、开发、测试和验收的依据。

**目标读者**:
- 产品经理：了解产品需求和功能定义
- 架构师：进行系统架构设计
- 开发工程师：进行功能实现
- 测试工程师：编写测试用例
- 项目经理：进行项目管理和进度跟踪
- 业务方：了解系统能力和使用方式

### 1.2 项目背景

**业务现状**:
医院信息化建设中，存在大量基于规则的业务场景，如传染病报卡、处方审核、病案质控等。这些场景的业务规则复杂多变，传统的硬编码方式存在以下问题：

1. **维护成本高**: 规则变更需要修改代码、测试、发布，周期长
2. **灵活性差**: 无法快速响应政策法规变化
3. **重复开发**: 每个业务场景独立开发规则判断逻辑
4. **难以管理**: 规则分散在各个系统中，缺乏统一管理

**解决方案**:
构建通用规则引擎平台，实现：
- 规则可视化配置，无需修改代码
- 统一的规则管理平台
- 规则引擎与业务系统解耦
- 快速响应业务规则变更

### 1.3 术语与缩略语

| 术语 | 说明 |
|-----|------|
| 规则引擎 | Rule Engine，用于执行业务规则的软件组件 |

## 二、项目概述

### 2.1 产品定位

通用规则引擎系统是一个**配置驱动的业务规则执行平台**，为医院各业务系统提供规则配置、管理和执行服务。

**核心价值**:
1. **业务与技术解耦**: 业务规则变更不依赖代码修改
2. **统一管理平台**: 所有业务规则集中管理
3. **提高响应速度**: 规则变更分钟级生效
4. **降低维护成本**: 减少重复开发和运维成本

### 2.2 产品目标

- **V1.0目标**（3个月）:
  - 支持传染病报卡、处方审核、病案质控三个业务场景
  - 提供可视化规则配置界面
  - 实现规则执行API
  - 规则执行性能<100ms

- **V2.0目标**（V1.0上线后3个月）:
  - 支持决策表、规则流等高级功能
  - 接入更多业务场景（临床路径、DRG分组等）
  - 规则推荐和优化建议
  - 分布式部署支持

- **版本控制**: Git

## 三、总体需求

### 3.1 业务需求

1. **规则可视化配置**: 业务人员无需编程即可配置规则
2. **规则统一管理**: 所有业务规则在一个平台管理
3. **规则快速生效**: 规则变更后立即生效，无需重启系统
4. **规则版本管理**: 支持规则版本记录和回滚
5. **规则执行日志**: 记录规则执行情况，便于追溯
6. **多业务场景支持**: 支持不同业务场景接入

### 3.2 用户需求

**目标用户**:
1. **业务人员**: 配置和管理规则
2. **IT人员**: 维护系统和接入新场景
3. **管理人员**: 查看规则执行情况和统计分析
4. **审计人员**: 查看操作审计日志

**用户画像**:
- 业务人员：熟悉业务规则，不具备编程能力
- IT人员：具备Java/Vue开发能力，了解Drools
- 管理人员：关注业务指标和系统运行状况
- 审计人员：需要完整的操作记录

### 3.3 干系人需求

| 干系人 | 关注点 | 需求 |
|-------|-------|------|
| 医院管理层 | 合规性、成本 | 符合法规要求、降低维护成本 |
| 业务科室 | 易用性、准确性 | 操作简单、规则准确 |
| 信息科 | 可维护性、稳定性 | 易于维护、系统稳定 |
| 开发团队 | 可扩展性、性能 | 架构清晰、性能达标 |
| 测试团队 | 可测试性 | 易于编写测试用例 |

## 四、功能需求

### 4.1 规则配置管理（核心功能）

#### 4.1.1 规则列表

**功能描述**: 展示所有规则的列表，支持筛选和搜索

**输入**:
- 场景编码（可选）
- 规则名称/编码（可选）
- 启用状态（可选）

**输出**:
- 规则列表（分页）

**主要字段**:
- 规则名称
- 规则编码
- 所属场景
- 规则类型
- 优先级
- 启用状态
- 创建时间
- 更新时间
- 操作按钮（查看/编辑/删除/测试/复制）

**用户操作**:
- 查看规则详情
- 编辑规则
- 删除规则
- 启用/禁用规则
- 测试规则
- 复制规则
- 导入/导出规则

#### 4.1.2 规则创建/编辑（参考原型图rule1.jpg）

**功能描述**: 可视化配置规则的条件和动作

**主要步骤**:

1. **基本信息配置**
   - 规则名称（必填）
   - 规则编码（必填，唯一）
   - 所属场景（必填）
   - 所属规则组（必填）
   - 规则类型（条件规则/决策表/脚本规则）
   - 优先级（0-1000，默认0）
   - 生效时间（可选）
   - 失效时间（可选）
   - 规则描述（可选）
   - 是否启用（默认启用）

2. **条件配置**（以传染病报卡为例）
   - **诊断满足规则**:
     - 支持"或者"/"并且"按钮切换
     - 支持多条件组
     - 每个条件组包含：
       - 关联条件（或者/并且）
       - 关联因素下拉（诊断名称/诊断编码/手术名称等）
       - 匹配符下拉（包含in/不包含not in/左匹配/模糊匹配等）
       - 匹配值输入（支持多选、自由输入、下拉选择）
       - 添加/删除条件按钮
     - 新增条件组按钮
     - 删除条件组按钮

   - **满足提示规则**（可选）:
     - 提示文案输入
     - 条件组配置（同诊断满足规则）

3. **动作配置**
   - 动作类型（返回结果/修改数据/调用服务/发送消息等）
   - 动作参数配置（JSON格式）
   - 支持多个动作
   - 动作执行顺序

4. **规则验证**
   - 语法验证
   - 字段存在性验证
   - 逻辑冲突检测

5. **规则保存**
   - 保存为草稿
   - 保存并启用
   - 保存并测试

#### 4.1.3 Query Builder组件（核心组件）

**功能描述**: 可视化的条件构建器

**主要功能**:
- 字段选择（从元数据动态加载）
- 操作符选择（根据字段类型动态变化）
- 值输入（支持单值、多值、范围、枚举等）
- AND/OR逻辑切换
- 条件组嵌套
- 条件添加/删除
- 条件组添加/删除
- 逻辑表达式实时预览（参考原型图rule2.jpg）

**支持的字段类型与操作符**（参考原型图rule3.jpg）:
详见《操作符定义与转换规则.md》

#### 4.1.4 规则详情查看

**功能描述**: 查看规则的详细配置信息

**展示内容**:
- 规则基本信息
- 条件配置（以可读的格式展示）
- 动作配置
- 版本历史
- 执行统计（触发次数、最后执行时间等）

#### 4.1.5 规则删除

**功能描述**: 删除不再需要的规则

**操作流程**:
1. 点击删除按钮
2. 弹窗确认
3. 执行删除
4. 记录审计日志

**约束条件**:
- 已启用的规则不能直接删除，需先禁用
- 删除操作不可恢复（建议改为禁用）

#### 4.1.6 规则启用/禁用

**功能描述**: 快速切换规则的启用状态

**操作方式**:
- 列表页Toggle开关
- 详情页启用/禁用按钮

**效果**:
- 禁用的规则不参与执行
- 状态变更立即生效
- 记录审计日志

#### 4.1.7 规则复制

**功能描述**: 基于现有规则快速创建新规则

**操作流程**:
1. 选择要复制的规则
2. 点击复制按钮
3. 生成新规则（规则编码和名称自动添加"_copy"后缀）
4. 跳转到编辑页面进行修改

#### 4.1.8 规则测试

**功能描述**: 在不影响生产环境的情况下测试规则

**测试界面**:
- 输入测试数据（JSON格式或表单形式）
- 执行测试按钮
- 展示测试结果
- 显示匹配的规则
- 显示执行日志
- 显示执行耗时

**测试数据模板**:
- 提供常用测试数据模板
- 支持保存自定义测试数据

## 五、非功能需求

### 5.1 性能需求

| 指标 | 目标值 | 说明 |
|-----|-------|------|
| 单次规则执行响应时间 | < 100ms | P95，简单规则 |
| 批量执行吞吐量 | > 1000 TPS | 并行执行 |
| 页面加载时间 | < 2s | 首屏加载 |
| 接口响应时间 | < 500ms | 规则配置API |
| 规则编译时间 | < 1s | 单条规则 |

## 八、接口需求

### 8.1 规则执行API

详见《prd.md》第三章和《业务场景详细需求.md》

**核心接口**:
1. POST /api/rule-engine/execute - 规则执行
2. POST /api/rule-engine/batch-execute - 批量执行
3. POST /api/rule-engine/test - 规则测试
4. POST /api/rule-engine/reload/{sceneCode} - 重载缓存

### 8.2 规则配置API

**规则管理**:
- POST /api/rule-engine/rule/create - 创建规则
- PUT /api/rule-engine/rule/update/{ruleId} - 更新规则
- DELETE /api/rule-engine/rule/delete/{ruleId} - 删除规则
- GET /api/rule-engine/rule/list - 查询规则列表
- GET /api/rule-engine/rule/{ruleId} - 查询规则详情
- POST /api/rule-engine/rule/copy/{ruleId} - 复制规则
- PUT /api/rule-engine/rule/status/{ruleId} - 启用/禁用规则

**场景管理**:
- GET /api/rule-engine/scene/list - 场景列表
- GET /api/rule-engine/metadata/{sceneCode} - 场景元数据

**规则组管理**:
- GET /api/rule-engine/group/list - 规则组列表
- POST /api/rule-engine/group/create - 创建规则组
- PUT /api/rule-engine/group/update/{groupId} - 更新规则组

**版本管理**:
- GET /api/rule-engine/version/list/{ruleId} - 版本列表
- POST /api/rule-engine/version/rollback - 版本回滚

**日志查询**:
- GET /api/rule-engine/log/list - 执行日志列表
- GET /api/rule-engine/log/{traceId} - 日志详情

### 8.3 接口规范

**请求格式**:
- Content-Type: application/json
- Authorization: Bearer {token}

**响应格式**:
```json
{
  "code": 200,
  "message": "success",
  "data": {}
}
```

**错误码**:
- 200: 成功
- 400: 参数错误
- 401: 未授权
- 403: 无权限
- 404: 资源不存在
- 500: 服务器错误
